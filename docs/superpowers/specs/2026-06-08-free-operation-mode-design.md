# 全站免费运营模式设计

日期：2026-06-08

## 1. 目标

为 Add WhatsApp 增加一个由服务端统一控制的全站运营模式：

- `free_access`：全站免费运营。
- `paid`：恢复套餐、额度、限额和支付。

首次上线默认使用 `free_access`。管理员可以在后台“套餐与限额”页面切换“启用收费模式”。

免费运营不是修改或清空用户套餐，而是在原有商业数据之上增加一层临时策略覆盖。进入免费模式时保留用户套餐、余额、订单、额度流水和支付记录；恢复收费后，已有付费用户恢复原套餐和余额，从未付费的用户使用免费版且余额为 0。

## 2. 已确认的产品规则

### 2.1 免费运营模式

- 所有登录用户获得商业版的全部功能能力。
- 不限制每日成功添加次数。
- 成功添加不扣额度。
- 客户端隐藏整个“探索方案”导航组。
- 套餐、用量、额度、账单入口全部隐藏。
- 客户端不出现余额不足、升级套餐或充值提示。
- 服务端继续记录成功添加用量，供运营统计使用，但不写负数扣费流水。
- 后台仍可查看历史套餐、余额、订单、支付事件和用量数据。

### 2.2 收费模式

- 恢复套餐能力、每日上限、工作台上限、模板上限和额度扣减。
- 恢复“探索方案”及套餐、用量、额度、账单入口。
- 恢复订单创建和支付入口。
- 用户原有套餐、余额和订单原样恢复。
- 从未购买过套餐或额度的用户继续使用免费版，余额为 0。

### 2.3 切换原则

- 不强制用户退出登录。
- 不终止正在运行的任务。
- 运行中任务不会因为切换而变得更严格：免费任务开启收费后仍免费；收费任务关闭收费后停止后续扣费。
- 切换后的新任务使用最新运营模式。
- 客户端可以在本次运行中自动更新导航，无需等待下次启动。

## 3. 核心架构

### 3.1 服务端是唯一权威来源

运营模式只能由服务端决定。客户端缓存用于短时容灾，不具有修改服务端计费结果的权力。

服务端维护一条当前全局策略：

```json
{
  "mode": "free_access",
  "version": 12,
  "effectiveAt": "2026-06-09T00:00:00+08:00",
  "updatedAt": "2026-06-08T15:30:00+08:00",
  "updatedBy": "admin-preview"
}
```

`version` 每次切换递增。客户端不得用低版本响应覆盖高版本缓存。

### 3.2 数据库存储

新增 `system_settings` 表，首期只保存运营模式，也允许以后增加维护模式等全局设置：

```sql
CREATE TABLE system_settings (
  key TEXT PRIMARY KEY,
  value_json TEXT NOT NULL,
  version INTEGER NOT NULL,
  updated_at TEXT NOT NULL,
  updated_by TEXT
);
```

键名使用 `billing_policy`。初始化数据：

```json
{
  "mode": "free_access",
  "effectiveAt": null
}
```

切换时必须在同一事务内：

1. 锁定 `billing_policy`。
2. 校验当前版本，防止两个管理员相互覆盖。
3. 更新模式、版本和生效时间。
4. 写入 `admin_audit_logs`。
5. 返回更新后的完整策略。

内存预览 runtime 提供等价存储和行为。

### 3.3 策略读取

新增认证接口：

```text
GET /v1/app-policy
```

返回：

```json
{
  "billing": {
    "mode": "free_access",
    "version": 12,
    "effectiveAt": "2026-06-09T00:00:00+08:00",
    "fetchedAt": "2026-06-08T15:31:00+08:00",
    "cacheExpiresAt": "2026-06-09T15:31:00+08:00",
    "keyId": "billing-policy-2026-01",
    "signature": "base64-ed25519-signature"
  },
  "minimumBillingClientVersion": "0.1.6"
}
```

`GET /v1/me/entitlements` 同时返回相同的 `billingPolicy`，减少登录和权益刷新时的额外请求。

后台 `GET /v1/admin/console` 返回当前策略、待生效策略和未支付订单数量。

策略响应使用服务端 Ed25519 私钥签名，客户端只内置公钥。离线免费缓存必须通过签名、版本、签发时间和过期时间校验；不能只信任可编辑的本地 JSON。

免费模式权益使用显式字段表达，不使用 `999999999` 一类伪无限值：

```json
{
  "billingMode": "free_access",
  "unlimitedDailyUsage": true,
  "hideBillingNavigation": true,
  "effectiveCapabilities": {
    "exportPreview": true,
    "secondaryWorkspace": true,
    "proxySettings": true,
    "customTemplates": true
  },
  "effectiveWorkspaceLimit": 5,
  "effectiveTemplateLimit": null
}
```

收费模式返回 `unlimitedDailyUsage: false`，并让 `effective*` 字段来自用户真实套餐。客户端只消费 `effective*` 字段执行权限判断，原始套餐字段仅用于收费页面展示。

## 4. 管理后台

### 4.1 开关位置

在“套餐与限额”页面顶部增加一个运营模式区：

- 标题：`收费模式`
- 开关文案：`启用收费模式`
- 关闭状态：`全站免费`
- 开启状态：`套餐与额度计费`
- 显示当前策略版本、更新时间、操作者和计划生效时间。

### 4.2 管理接口

新增：

```text
PUT /v1/admin/billing-policy
```

请求：

```json
{
  "mode": "paid",
  "effectiveAt": "2026-06-09T00:00:00+08:00",
  "expectedVersion": 12,
  "reason": "结束免费推广期"
}
```

允许 `effectiveAt` 为空，表示立即生效。默认 UI 推荐次日 Asia/Shanghai `00:00` 生效。

错误：

- `BILLING_POLICY_VERSION_CONFLICT`
- `BILLING_POLICY_MODE_INVALID`
- `BILLING_POLICY_EFFECTIVE_AT_INVALID`

### 4.3 二次确认

开启收费时确认框必须显示：

- 生效时间。
- 当前未支付订单数量。
- 正在运行的免费任务不会被中途收费。
- 新任务将在生效后按套餐、余额和每日上限处理。
- 旧客户端可能需要升级。

关闭收费时确认框必须显示：

- 已产生的合法扣费不退还。
- 用户套餐、余额和订单不会清空。
- 新任务将免费执行，支付入口将关闭。

所有切换写入审计日志，动作名为 `billing.policy_update`。

## 5. 客户端策略缓存

### 5.1 缓存内容

按云端账号保存最近一次成功策略：

```json
{
  "mode": "free_access",
  "version": 12,
  "effectiveAt": "...",
  "fetchedAt": "...",
  "cacheExpiresAt": "...",
  "keyId": "billing-policy-2026-01",
  "signature": "..."
}
```

免费策略缓存有效期为 24 小时。收费策略也缓存，但收费策略过期后仍按收费处理，不降级为免费。签名无效、字段缺失或版本回退的缓存按损坏处理。

### 5.2 读取优先级

1. 服务端返回的最新有效策略。
2. 未过期的本地策略缓存。
3. 无缓存、缓存损坏或免费缓存过期时，默认 `paid`。

服务端恢复后立即以高版本服务端策略为准。

### 5.3 刷新时机

- 软件启动并恢复登录后。
- 登录或注册成功后。
- 窗口重新获得焦点时，距离上次刷新超过 60 秒才请求。
- 每 5 分钟轮询一次。
- 开始新任务前强制刷新一次；网络失败时进入缓存规则。
- 当前任务结束、取消或失败后刷新一次。
- 支付成功和权益刷新后同步刷新。

请求失败不弹连续错误通知，只更新内部同步状态。只有用户开始任务且没有可用策略时才显示阻断提示。

## 6. 客户端界面

### 6.1 免费模式

- 隐藏 `plansToggle` 和 `plansSubnav` 整组。
- 如果用户当前停留在套餐、用量、额度或账单页，策略切到免费后，在没有运行任务时跳回默认工作页。
- 正在运行任务时不改变当前页面或任务控件；只缓存待应用导航状态，任务结束后再隐藏探索方案。
- 功能守卫使用统一的“免费运营能力覆盖”，其能力与商业版对齐，不读取用户真实套餐能力。
- 工作台、代理、导出预检和模板能力全部开放。
- UI 不显示余额、价格、充值、升级或套餐名称。

### 6.2 收费模式

- 在空闲状态下立即显示“探索方案”。
- 正在运行任务时可以显示导航，但不能改变该任务的计费策略。
- 开始新任务前根据最新权益执行余额、每日上限和功能校验。
- 老用户恢复原套餐和余额；新用户显示免费版、余额 0。

### 6.3 旧客户端保护

服务端策略包含 `minimumBillingClientVersion`。

当模式为 `paid` 且客户端版本低于最低计费版本时：

- 禁止开始新任务。
- 不允许创建支付订单。
- 显示“请升级到最新版后继续使用”。
- 不强制退出登录。
- 不影响已启动任务完成。

免费模式不因版本过旧阻断任务，除非另有安全升级要求。

## 7. 任务级计费策略

### 7.1 为什么需要任务快照

如果只在每次成功添加时读取全局开关，管理员开启收费后，正在运行的免费任务会从某一条开始突然扣费。任务必须在启动时保存策略快照，同时遵守“只能变宽松”的结算规则。

### 7.2 在线任务会话

新增：

```text
POST /v1/task-billing-sessions
```

请求包含 `taskId`、`workspaceId`、客户端版本和设备 ID。响应：

```json
{
  "sessionId": "billing_session_...",
  "taskId": "task_...",
  "mode": "free_access",
  "policyVersion": 12,
  "startedAt": "...",
  "expiresAt": "...",
  "status": "active"
}
```

任务会话默认最长 24 小时。任务完成或取消时调用：

```text
POST /v1/task-billing-sessions/:id/close
```

新增持久化表：

```sql
CREATE TABLE task_billing_sessions (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id),
  task_id TEXT NOT NULL,
  workspace_id TEXT NOT NULL,
  mode TEXT NOT NULL,
  policy_version INTEGER NOT NULL,
  plan_id_snapshot TEXT,
  started_at TEXT NOT NULL,
  expires_at TEXT NOT NULL,
  closed_at TEXT,
  status TEXT NOT NULL,
  UNIQUE (user_id, task_id)
);
```

API 重启后必须能够继续识别运行中任务，不能把任务策略只放在进程内存中。

### 7.3 成功添加上报

现有 `POST /v1/credits/consume` 增加必填 `billingSessionId`。

服务端行为：

- 会话为 `free_access`：写免费用量事件，增加日/月成功添加统计，不写 `amount=-1` 的额度流水。
- 会话为 `paid` 且当前全局模式仍为 `paid`：按会话中的套餐快照和现有幂等键扣减额度。
- 会话为 `paid` 但当前全局模式已变为 `free_access`：从全局免费生效时间起按免费用量处理，不退还生效前已经产生的合法扣费。
- 会话过期：返回 `TASK_BILLING_SESSION_EXPIRED`。
- 会话关闭：返回 `TASK_BILLING_SESSION_CLOSED`。
- 会话与用户、任务或工作台不匹配：返回 `TASK_BILLING_SESSION_MISMATCH`。
- 相同幂等键重复上报：返回原结果，不重复统计或扣费。

为保持账本语义清晰，免费用量不写入 `credit_ledger`。新增 `task_usage_events` 保存所有成功添加的最小幂等事件：

```sql
CREATE TABLE task_usage_events (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id),
  task_id TEXT NOT NULL,
  billing_session_id TEXT NOT NULL,
  mode TEXT NOT NULL,
  idempotency_key TEXT NOT NULL UNIQUE,
  contact_hash TEXT,
  created_at TEXT NOT NULL
);
```

`usage_daily` 和 `usage_monthly` 由该幂等事件驱动更新。

### 7.4 离线免费容灾

当服务端不可达、客户端持有未过期的 `free_access` 缓存时，允许启动离线免费任务：

- 本地任务记录策略版本和缓存到期时间。
- 最晚只能运行到该免费缓存到期时间，且总保护期不超过 24 小时。
- 成功结果进入现有待同步队列，不扣本地余额。
- 恢复联网后携带已签名的策略凭证和任务启动策略信息同步为免费用量。
- 服务端只接受仍在容灾窗口内产生的免费事件。

这是一项有界容灾能力，不提供永久离线免费。由于桌面客户端无法成为绝对可信执行环境，24 小时窗口是可用性与防滥用之间的明确取舍。

### 7.5 任务到期

- 会话到期后不自动改成收费并继续扣款。
- 当前任务暂停，不再处理新联系人。
- 提示用户联网刷新策略并重新开始任务。
- 已完成的成功添加按原会话结算。
- 不允许向已启动任务动态追加名单；追加名单必须创建新任务和新计费会话。

## 8. 功能权限和工作台

免费模式下服务端和客户端均使用商业版能力覆盖：

- 导出预检可用。
- 代理设置可用。
- 自定义模板不限。
- 第二工作台可用。
- 默认工作台上限使用商业版当前上限 5。

“不限每日次数”不等于“不限工作台”。首期仍使用商业版默认 5 个工作台，超过 5 个继续走人工扩容，防止资源失控。

当前客户端商业版模板上限为不限，而服务端套餐目录仍存在数值上限。实施前统一为显式能力配置：免费运营覆盖和商业版均使用 `templateLimit: null`，避免客户端和服务端口径不一致。

工作台租约接口必须读取当前全局模式：

- `free_access`：使用商业版工作台上限。
- `paid`：使用用户真实套餐上限。

进入收费模式时，不强制关闭已经存在的超额工作台租约：

- 已有租约允许续租到对应进程退出。
- 不允许再创建新租约，直到活跃数量回落到套餐上限以下。
- 管理员仍可手动释放异常租约。

## 9. 支付链路

### 9.1 免费模式下暂停新交易

免费模式下：

- 客户端隐藏套餐和额度购买入口。
- `POST /v1/orders` 返回 `BILLING_DISABLED`。
- 支付二维码、支付链接和人工收款接口不再为新订单生成交易。
- 支付渠道密钥、证书和回调配置保持不变。

### 9.2 切换前订单

切换到免费模式前已经创建的未支付订单：

- 保持原有约 5 分钟有效期。
- 已经打开的支付页面可以继续支付。
- 支付回调必须继续正常接收、验签、幂等入账。
- 到账后的套餐和余额正常保存，但免费期间不展示、不限制用户。
- 恢复收费后自动显示并生效。

### 9.3 回调永不随开关关闭

微信、支付宝、ZPAY 和人工入账的回调或补偿流程始终可用。运营模式只控制“能否创建新交易”，不控制“是否处理已经发生的资金事实”。

## 10. 定时生效和连续切换

### 10.1 定时生效

后台允许立即生效或定时生效。默认推荐次日 Asia/Shanghai `00:00`。

服务端读取策略时，根据 `effectiveAt` 计算实际模式，不依赖后台页面或定时任务恰好在线。到达生效时间后，任何 API 实例都应得到相同结果。

### 10.2 连续切换

- 每次修改递增 `version`。
- 新设置覆盖尚未生效的旧计划。
- `expectedVersion` 防止并发管理员覆盖。
- 客户端只接受版本更高，或相同版本但服务端时间更新的策略。
- 任务会话始终保留创建时的版本和模式。结算时只允许全局 `paid -> free_access` 使任务变得更宽松，不允许 `free_access -> paid` 使任务中途开始扣费。

## 11. 异常边界

### 11.1 服务端或数据库不可用

- 客户端使用最近一次有效缓存。
- 免费缓存超过 24 小时后，新任务按收费模式处理。
- 无任何缓存时默认收费。
- 已运行任务按任务会话或离线保护期处理。
- 后台开关更新失败时保持原策略，不允许 UI 乐观显示成功。

### 11.2 客户端时间错误

- 在线策略、生效时间和任务会话使用服务器时间。
- 离线缓存只允许缩短免费窗口，不允许因为修改本机时间延长窗口。
- 客户端保存最近一次服务端时间和本地单调时钟基准；检测到系统时间明显回拨时默认收费并要求联网刷新。
- 桌面客户端不是绝对可信环境。签名和 24 小时窗口用于限制常规篡改与重放，最终同步仍以服务端当前时间和凭证过期时间为准。

### 11.3 多设备和多 API 实例

- 策略存储在 PostgreSQL，不保存在单个 API 进程内存。
- API 进程可以短缓存 5 至 15 秒，但版本变化后必须尽快失效。
- 所有设备最终读取相同策略。
- 单台设备仍可能在刷新窗口内短暂使用旧策略，任务快照保证结算一致。

### 11.4 管理员误操作

- 二次确认。
- 默认定时生效。
- 审计日志记录前值、后值、版本、原因、操作者和 IP。
- 后台提供“取消待生效变更”。
- 回滚通过创建一个更高版本的新策略完成，不直接修改历史审计。

### 11.5 支付与切换竞态

- 创建订单时在服务端事务边界内读取当前策略。
- 免费模式生效前成功创建的订单可继续支付。
- 免费模式生效后到达的创建订单请求拒绝。
- 支付成功回调按订单事实入账，不重新检查当前运营模式。

### 11.6 开始任务与切换竞态

- 创建任务计费会话时由服务端一次性确定模式。
- 会话创建成功即获得该策略，不以客户端收到后台开关消息的先后顺序为准。
- 后台生效时间之前创建的是旧策略，生效时间之后创建的是新策略。

## 12. API 错误与客户端提示

新增错误码：

- `BILLING_DISABLED`
- `BILLING_POLICY_VERSION_CONFLICT`
- `BILLING_POLICY_MODE_INVALID`
- `BILLING_POLICY_EFFECTIVE_AT_INVALID`
- `BILLING_CLIENT_UPGRADE_REQUIRED`
- `TASK_BILLING_SESSION_REQUIRED`
- `TASK_BILLING_SESSION_EXPIRED`
- `TASK_BILLING_SESSION_CLOSED`
- `TASK_BILLING_SESSION_MISMATCH`

客户端提示原则：

- 后台切换不弹强制退出提示。
- 运行中任务不弹“开始收费”打断提示。
- 新任务被阻断时才解释升级、余额、限额或联网要求。
- 免费模式下不出现任何收费引导。

## 14. 分阶段实施

### 阶段 1：服务端策略底座

- 数据库表和默认免费策略。
- 内存/PostgreSQL runtime API。
- 管理接口、版本控制和审计。
- 权益接口返回运营模式。

### 阶段 2：后台开关

- 套餐与限额页运营模式区。
- 立即/定时生效。
- 二次确认、未支付订单提示和冲突处理。

### 阶段 3：客户端界面与能力覆盖

- 策略缓存与刷新。
- 免费模式隐藏探索方案。
- 商业版能力覆盖。
- 无缓存默认收费和 24 小时免费容灾。

### 阶段 4：任务计费会话

- 在线任务会话。
- 免费用量事件和收费扣费分流。
- 会话过期、关闭、幂等和待同步兼容。

### 阶段 5：支付和工作台边界

- 免费模式拒绝新订单。
- 保留支付回调和补偿。
- 工作台租约按模式判定，并保护已有租约。

### 阶段 6：兼容、发布和验证

- 最低计费客户端版本。
- 全量自动化测试。
- 先部署服务端和后台，保持默认免费。
- 发布支持新策略的客户端。
- 确认新版本覆盖率后，后台才允许真正开启收费。

## 15. 发布与回滚

推荐发布顺序：

1. 部署数据库迁移。
2. 部署默认 `free_access` 的服务端。
3. 部署后台开关，但先不启用收费。
4. 发布支持策略和任务会话的新客户端。
5. 验证免费模式全链路。
6. 设置 `minimumBillingClientVersion`。
7. 选择定时生效开启收费。

回滚原则：

- 发现异常时创建更高版本的 `free_access` 策略。
- 不删除订单、额度流水或审计历史。
- 不关闭支付回调。
- 已启动的收费任务在全局免费生效后停止后续扣费；生效前已经产生的合法扣费不自动退款，必要时由管理员人工补偿。

## 16. 非目标

首期不包含：

- 按用户、地区或灰度分组免费。
- 优惠券、试用天数或促销价。
- 免费期自动退款。
- 自动关闭用户已有工作台。
- 永久离线使用。
- 修改历史套餐、余额、订单或额度流水。
